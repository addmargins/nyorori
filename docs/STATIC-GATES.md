# Static gate implementation and resolver boundary

G2 uses the lockfile-pinned ESLint `Linter` API, a supplied flat configuration, the gate's own TypeScript parser/plugin and `noInlineConfig: true`. It lints text from Git blobs. It does not discover a checkout's ESLint configuration, import its plugins, resolve its `node_modules`, or execute its application. Existing rule debt is compared at the cccc matched-unit level; new diagnostics are not limited to added start lines. This catches a fifth parameter added several lines after a function declaration. Counted occurrences cannot borrow an exemption from another matched unit, including same-line class methods.

The hard rules cover dynamic `Function`/`eval`/VM/constructor mechanisms, parameter count, callback depth, bidi controls and suppression comments. Test callbacks are exempt from callback-depth blocking. Only `this: void` is excluded from parameter count. Constructor access is conservatively prohibited, including computed literal spellings; this can require policy review for legitimate reflection. No finite syntax denylist can prove the absence of all forms of dynamic JavaScript.

S4, S9, S10 and S11 preserve evidence. Normalized S9 row comparisons use the lockfile-pinned Prettier with explicit parser options, and count parser token rows rather than comments. Lost-function binding checks inspect AST bindings. Declaration files are parsed separately and executable bodies/initializers are rejected despite their complexity-scope exclusion. Product-to-test scope moves route S11 even when the Git blob is unchanged. New product imports into excluded or test-only implementations fail the dependency boundary.

G3 deliberately uses a lockfile-pinned TypeScript AST graph instead of dependency-cruiser. Import/export, literal `import()`, literal CommonJS `require()` and TypeScript import-equals edges are inspected without executing configuration. Relative paths support explicit JS/TS files, JS-to-TS source fallback and index modules. Ambiguous/unresolved relative references and nonliteral module references are `INCONCLUSIVE`; a partial graph is never described as complete. Strongly connected components use an iterative traversal, and new cyclic edges are compared against B after verified file-rename mapping. New forbidden policy edges fail independently. S3 identifies fan-out increases and multiple new modules with a sole common importer.

The initial supported resolver profile is relative-file JS/TS plus declared npm packages and Node builtins. It does **not** certify TypeScript `paths`/`baseUrl`/`extends`/project references, `rootDirs`, `moduleSuffixes`, custom conditions, `moduleResolution`, package-resolution flags, symlink/type-root/plugin/JSX-runtime resolution settings, package import maps, workspace/file/link dependencies, self/workspace package imports, undeclared bare aliases, or arbitrary bundler resolution. Both conventional `tsconfig*.json`/`jsconfig*.json` and `.jsonc` metadata are read strictly from blobs and parsed as data (comments, trailing commas and escaped keys included). Conventional Vite/Vitest/Webpack/Rollup/esbuild/Rspack/RSBuild/Next/Nuxt/Astro/Svelte/Vue/Babel/tsup/unbuild resolver configs, `.babelrc`, `.swcrc`, `.parcelrc` and `angular.json` are rejected by presence: this profile does not execute or certify their mappings, even when the configuration looks harmless. Configuration-only changes still run G3. Recognized unsupported metadata causes `DEPENDENCY_RESOLUTION_UNSUPPORTED`; malformed or nonregular resolver metadata is rejected. Those projects need an independently tested trusted resolver profile before enforcing G3. Metadata comes from Git blobs and is never executed. Runtime-created/aliased loaders and arbitrary bundler plugins remain outside a static import graph's proof; G3 is a structural policy check, not a general JavaScript call graph or a malicious-code detector.

These boundaries are deployment requirements, not reasons to mark missing analysis as PASS. The JSON reports retain exact issue codes, and observe mode preserves them for pilot calibration.
